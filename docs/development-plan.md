# 德国卖家库独立脚本开发与版本管理计划

本文件记录用户确认的实施合同。首个独立版本为 1.0.0，仅上传独立新版；原项目旧流程通过 README 对照说明，不上传旧版源码。

## 1. 业务合同

原项目：产品链接/结果表 → 产品页核验卖家 → 店铺抓取 → 初筛 → 历史库排除 → SellerSprite 补全 → 配送/变体/720 天/子体销量分段 → 部分新品近 7 天销量 → 详情 → Excel。

新版：Excel B 列卖家 → 店铺抓取 → 初筛 → SellerSprite 补全 → 配送/变体/180 天 → 全部合格 ASIN 近 7 天销量 → 通过者详情 → Excel。

- 初筛保持评论数 <300、评分 ≥3.5、价格 7.99–60.00 欧元，价格包含两端。
- 保留 FBA、变体数量非空且 ≤3。
- 上架日期按任务创建时固定 UTC 日期计算，保留 0–180 天；缺失、非法、未来日期和第 181 天起排除。
- 删除历史库连接、健康检查、查询、配置及 mysql2 依赖。
- 删除原子体销量分段门槛：0–365 天 ≥100、366–550 天 ≥200、551–720 天 ≥300；子体销量保留原值，仅展示。
- 删除仅 0–30 天且子体销量为空才进入销量判断的条件。所有合格候选进入 sales_pending，高子体销量不能直接保留。
- 复用现有销量 API、请求格式、固定 daily_sales_minimum=3 和前七个完整 UTC 日窗口。精确 yes 保留，No 排除，协议/网络失败暂停并允许续跑。
- 保留现有翻页、提取、代理、邮编、并发、重试和补全算法，不在本版同时重写分页算法。

## 2. 项目隔离与接口

独立项目位于原项目下 `scripts/de-seller-library`，GitHub 根目录直接存放独立项目。复制当前代码作为基线，后续只改独立副本，不通过运行时 import 复用父项目源码，不使用父项目 node_modules。

- 独立 src、config、package/lockfile、tests、run.ps1、output 和 .git。
- 输入默认“卖家数据”工作表，B2 起读取，优先超链接，兼容链接文本/直接 ID。保留原始行、名称、链接和解析结果。
- 重复卖家只创建一次抓取任务；所有来源行仍在 source_seller_inputs 审计。空行留痕，非空非法行在联网前报错。
- 不构造假产品 ASIN，不将原表卖家标记为已核验。产品核验阶段明确 skipped，source_stores 使用 direct_input。
- 历史筛选明确 skipped，后续补全检查“初筛完成且历史筛选显式跳过”。没有历史查询 CLI。
- 新数据库 schema 18，不修改、迁移或续跑原项目 schema 17。
- 任务保存工作流 ID、输入哈希、有效配置哈希、代码指纹、版本和固定基准日期。合同不一致时拒绝续跑；改业务规则后新建任务。
- 运行索引与所有输出限定独立项目内，原始店铺出现记录和多卖家来源继续保留。

统一入口：inspect-input；pipeline --input <Excel> --limit 1；pipeline --input <Excel>；status --run <ID>；pipeline --resume <ID>。续跑不能同时提供新的 input/config/limit。inspect-input 不联网。

保留 19 列、5 工作表；完整表包括全部最终保留行，每行只进入一个年龄分组。表名沿用“产品数据、0-30天、31-365天、366-550天、551-720天”，31–365 表本版实际为 31–180 天，最后两表只有表头。导出分组与删除的销量分段配置解耦。

## 3. 文档与 GitHub

目标：https://github.com/1012zeng/Amazon_seller_asin 。保留现有初始化提交，在 feature 分支开发；通过验收后合入 main 并创建注释标签 v1.0.0。后续标签不移动，修复/功能/破坏兼容分别按补丁/次/主版本管理。

README 记录当前版改变、旧业务流程、完整规则对照、输入/安装/配置/运行/续跑、输出与真实验收边界。另维护 CHANGELOG、此计划、验收报告和原文件哈希基线。

仅提交源码、示例配置、锁文件、合成测试和文档；忽略真实 Excel、SQLite/WAL、日志、浏览器状态、凭据、私有配置和 node_modules。首次提交前检查，不把秘密写入任何提交历史。

Windows CI 固定 Node 24.14.0、pnpm 11.5.2，只运行锁定依赖安装、类型检查和离线测试，不调用业务服务。Git 连接只使用命令级代理设置，不修改全局配置。

回滚用独立 worktree 检出标签并安装其锁文件；代码回滚不覆盖数据库。需恢复 main 使用反向提交保留历史，不强推。仓库无法回滚到未上传的原项目旧版。

## 4. 验收与交付

离线验证：输入类型及非法行、去重审计、初筛边界、0/30/31/180/181 天、日期异常、配送/变体、子体销量空/零/高均进入销量判断、yes/No、超时/协议错误、失败续跑、幂等任务、跨合同拒绝续跑、五表/19 列、最终行数一致、历史库完全缺席、父项目哈希不变。

真实验证只跑首个卖家 Moisture Soarlin / AAX6N1QZ7A0WK，统计本次每个阶段，不把旧抓取的 2,556 个不同 ASIN 当作固定目标。没有候选触发的环节明确记录未实测；服务失败和抓取不完整不能宣称全链路通过。开发分支可先保存进度，正式标签等待验收完成。

默认交付独立项目、测试、单卖家真实验证、README、GitHub 提交和首版标签。不会自动开启 12,033 个卖家的全量任务。共享代理、服务和额度仍需避免同时大批量占用。

## 5. 用户追加规则：v1.1.0

2026-09-18 用户要求初筛评分为 NA 或评论数为 NA 的数据也保留。实现为每个字段独立判断：缺失允许通过该项，有值继续执行原门槛；价格及所有后置条件不变。

改动覆盖实际抓取选择器、SQL 初筛及原因统计、最终表可空约束、TypeScript 类型和 Excel NA 显示；新增对应贯穿链路测试。真实页面确认旧通用下划线选择器会把价格当评论数，限定为评论区域后重抓，不清洗或改写旧记录。独立项目升级到 schema 19，新工作流和代码指纹拒绝 schema 18 任务续跑。发布 v1.1.0，保留 v1.0.0 标签和原项目文件。

本次真实验证为首个卖家第一页的生产提取和 SQLite 初筛，后续业务链路通过离线模拟验证；未启动全店或全部卖家任务。具体数量和边界记录到 acceptance-v1.1.0.md。
